# Experiment 08 — Shape CNN Evaluation and Feature Maps

## Objective

Does the trained shape classifier generalize to unseen generated images, and what happens inside its convolutional layers?

The previous experiment demonstrated that a CNN could perfectly fit the generated training dataset.

However, training accuracy alone cannot determine whether a model generalizes.

This experiment introduces:

1. a held-out test set,
2. independent test evaluation,
3. a confusion matrix,
4. inspection of learned convolution filters,
5. visualization of intermediate feature maps.

The experiment therefore studies both:

```text
model performance
+
internal representations
```

## Concepts

### Train/test evaluation

The dataset contains:

```text
1000 images
```

and is divided into:

```text
800 training images
200 test images
```

The training data is used to update model parameters.

The test data is not used during training.

Conceptually:

```text
1000 images
     ↓
train/test split
     │
     ├── 800 train
     │      ↓
     │   learn parameters
     │
     └── 200 test
            ↓
         evaluate
```

This allows test accuracy to measure performance on images that were not directly used to optimize the CNN.

### Dataset classes

The training split contained:

```text
389 circles
411 squares
```

The test split contained:

```text
118 circles
82 squares
```

The class labels are:

```text
0 → circle
1 → square
```

### CNN architecture

The network is:

```text
32×32 grayscale image
        ↓
Conv2d 1 → 16
        ↓
ReLU
        ↓
MaxPool
        ↓
Conv2d 16 → 32
        ↓
ReLU
        ↓
MaxPool
        ↓
Flatten
        ↓
Linear
        ↓
1 logit
```

The model contains two trainable convolutional layers.

### First convolution

The first convolution is:

```python
nn.Conv2d(
    in_channels=1,
    out_channels=16,
    kernel_size=3,
    padding=1
)
```

For one image:

```text
[1, 32, 32]
      ↓
Conv2d
      ↓
[16, 32, 32]
```

The layer learns 16 convolution filters.

Each filter produces one feature map.

### First pooling operation

After the first convolution and ReLU:

```text
[16, 32, 32]
```

Max pooling reduces the spatial dimensions:

```text
[16, 32, 32]
      ↓
MaxPool
      ↓
[16, 16, 16]
```

The number of channels remains 16.

Only the spatial resolution changes.

### Second convolution

The second convolution is:

```python
nn.Conv2d(
    in_channels=16,
    out_channels=32,
    kernel_size=3,
    padding=1
)
```

It receives the 16 feature maps from the previous block and produces 32 new feature maps.

For one image:

```text
[16, 16, 16]
      ↓
Conv2d
      ↓
[32, 16, 16]
```

Each output filter can combine information from all 16 previous input channels.

### Filter vs feature map

A convolution filter and a feature map are different things.

A **filter** contains learned model parameters.

For example:

```text
3 × 3 learned weights
```

A **feature map** is the result of applying a filter to a particular image.

Conceptually:

```text
image
+
learned filter
      ↓
convolution
      ↓
feature map
```

The same learned filter can produce different feature maps for different images.

### First-layer filter tensor

The first convolution weights have shape:

```text
[16, 1, 3, 3]
```

This means:

```text
16 output filters
1 input channel
3 × 3 kernel
```

Each of the 16 filters receives the grayscale image.

### Second-layer filter tensor

The second convolution weights have shape:

```text
[32, 16, 3, 3]
```

This means:

```text
32 output filters
16 input channels
3 × 3 kernel for each input channel
```

Each output filter therefore combines information from all 16 feature maps generated by the previous convolutional block.

### Learned representations

The first convolution transforms the original image into:

```text
16 feature maps
```

The second convolution combines those representations into:

```text
32 new feature maps
```

Conceptually:

```text
pixels
  ↓
first convolution features
  ↓
combinations of features
  ↓
second convolution features
  ↓
classification
```

The experiment does not prove that individual feature maps correspond to simple human concepts such as "curve detector" or "corner detector".

They should be interpreted as learned internal representations.

### Evaluation mode

After training:

```python
model.eval()
```

places the network in evaluation mode.

This is the correct general pattern for inference.

The current network does not contain Dropout or BatchNorm, so evaluation mode does not change the numerical behavior of those layers, but it becomes important in more complex networks.

### `torch.no_grad()`

Evaluation and feature inspection use:

```python
with torch.no_grad():
```

This prevents PyTorch from recording operations for backpropagation.

During evaluation:

```text
forward pass
→ predictions
```

is required.

But:

```text
gradients
backpropagation
parameter updates
```

are not required.

## Hypothesis

The CNN should classify the training data accurately.

If the learned convolutional features generalize to new generated shapes, test accuracy should also remain high.

The test accuracy may differ from training accuracy because the test images were not used to update the network parameters.

Intermediate feature maps should also confirm the expected tensor transformations through the convolutional layers.

## Implementation

The script:

1. Generates 1000 synthetic circle and square images.
2. Adds the grayscale channel dimension.
3. Splits the dataset into 80% training and 20% testing.
4. Trains the CNN using only the training images.
5. Calculates training accuracy.
6. Calculates test accuracy.
7. Calculates the generalization gap.
8. Produces a confusion matrix.
9. Displays several example predictions and sigmoid scores.
10. Prints the learned first-layer convolution filters.
11. Selects one unseen test image.
12. Applies the first convolution to that image.
13. Visualizes the resulting 16 feature maps.
14. Applies the first convolutional block and second convolution.
15. Visualizes part of the second convolution's feature maps.

## Interpretation

### Generalization result

The CNN achieved:

```text
100% training accuracy
100% test accuracy
```

for this particular synthetic dataset and split.

Unlike the previous experiment, test performance is now measured using images that were not directly used during training.

This provides evidence that the model generalizes to the held-out samples generated by the same synthetic data process.

However, it does not demonstrate generalization to arbitrary real-world images.

### Why the task is easy

The generated task is intentionally simple.

Circles and squares:

* have fixed sizes,
* use the same brightness,
* use the same black background,
* contain no noise,
* contain no rotation,
* contain no scaling variation,
* come from the same generator.

The CNN can therefore learn highly reliable patterns for this restricted problem.

The perfect test result should be interpreted in that context.

### Possible dataset shortcuts

The model may not be learning an abstract concept of "circle" and "square".

For example, circles and squares have different pixel distributions and areas.

The CNN may exploit any reliable feature that separates the classes.

The experiment therefore demonstrates successful classification, but not which exact visual reasoning strategy the network uses.

### Feature inspection

The learned convolution filters are model parameters.

The feature maps are outputs generated by applying those filters to a specific image.

The relationship is:

```text
learned filter
+
input representation
      ↓
convolution
      ↓
feature map
```

The first layer produces 16 feature maps directly from the grayscale image.

The second layer receives those 16 channels and produces 32 more complex representations.

This demonstrates how deeper convolutional layers progressively transform image representations.

## Conclusion

This experiment demonstrates both held-out CNN evaluation and inspection of internal convolution representations.

The main pipeline is:

```text
generated images
      ↓
train/test split
      ↓
CNN training
      ↓
held-out evaluation
      ↓
internal feature inspection
```

The verified run achieved perfect accuracy on the generated training and test sets.

The experiment also confirms the expected internal tensor transformations:

```text
input
[1, 1, 32, 32]

      ↓ Conv1

[1, 16, 32, 32]

      ↓ ReLU + MaxPool

[1, 16, 16, 16]

      ↓ Conv2

[1, 32, 16, 16]
```

This provides direct evidence that convolutional layers transform images into multiple learned feature channels.

## Limitations

This experiment remains intentionally artificial.

Important limitations include:

* synthetic images,
* fixed circle radius,
* fixed square size,
* fixed brightness,
* black backgrounds,
* no image noise,
* no rotations,
* no scaling variation,
* one random seed,
* one train/test split,
* no validation set,
* no cross-validation,
* possible duplicate or near-duplicate generated samples,
* possible shape-area shortcuts,
* full-batch CPU training,
* no data augmentation,
* no external dataset,
* no probability calibration analysis.

Train and test samples also come from exactly the same generator.

Therefore, the test distribution is extremely similar to the training distribution.

A more challenging experiment should introduce greater variation or use a real image dataset.

## Check yourself

### Why use a train/test split?

The training set is used to learn model parameters.

The test set remains outside training and provides an independent estimate of performance on unseen samples.

### What does a generalization gap of zero mean here?

In this run:

```text
training accuracy = 100%
test accuracy     = 100%
```

Therefore:

```text
generalization gap = 0 percentage points
```

This means training and test accuracy are identical for this particular split.

It does not prove that the model will achieve 100% accuracy on every possible future dataset.

### What is the difference between a filter and a feature map?

A filter contains learned weights.

For example:

```text
3 × 3 kernel weights
```

A feature map is the output produced when that filter is applied to an input.

```text
filter
+
input
↓
feature map
```

### Why does the second convolution use 16 input channels?

The first convolution produces 16 feature maps.

After ReLU and pooling, those 16 feature maps become the input channels of the second convolution.

### Why does the second convolution produce 32 feature maps?

The second convolution has:

```python
out_channels=32
```

Each output filter creates one output feature map.

Therefore:

```text
32 filters
→
32 output feature maps
```

### Why do spatial dimensions shrink after pooling?

Max pooling replaces local regions with their maximum values.

With:

```python
kernel_size=2
```

the spatial dimensions are reduced approximately by half:

```text
32 × 32
↓
16 × 16
```

The number of channels remains unchanged.

### Why use `torch.no_grad()` during inspection?

Feature inspection and evaluation do not require training.

Using:

```python
with torch.no_grad():
```

prevents PyTorch from recording the operations needed for backpropagation.

This reduces unnecessary memory use and computation.

### Why is `model.eval()` different from `torch.no_grad()`?

`model.eval()` changes the behavior of layers that have different training and evaluation modes, such as Dropout and BatchNorm.

`torch.no_grad()` disables gradient recording.

They solve different problems.

The current architecture does not contain Dropout or BatchNorm, but using both patterns prepares the code for more complex networks.

### Does 100% test accuracy prove the CNN understands shapes?

No.

It proves that the trained model correctly classified the 200 held-out samples in this particular synthetic experiment.

The model may use any statistical feature that separates circles and squares.

The experiment does not establish that the CNN has learned a human-like abstract understanding of geometric shapes.
